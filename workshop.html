00 — for the presenterThe red thread

A proxy is a stand-in with the same interface as the real thing — so you can add caching, guards and logging without the client or the real class ever finding out.

02 — the patternWhat a proxy actually is

  
A proxy is an object with the same interface as a real service. Clients talk
    to the proxy; the proxy controls whether, when and how the real service is used.
    Because the interface matches, the client cannot tell the difference — and does not need to.

Demo 2 · caching & lazy loading
code/src/02-virtual-proxy.ts

    


class CachingImageProxy implements ImageService {
  private cache = new Map();
  private real = null;              // not created yet — lazy!

  fetch(name) {
    const hit = this.cache.get(name);
    if (hit !== undefined) return hit;   // 1. cache first
    this.real ??= new RemoteImageService(); // 2. build it on first real use
    const data = this.real.fetch(name);   // 3. delegate
    this.cache.set(name, data);           // 4. remember
    return data;
  }
}

03 — protection proxySame shape, different job

  
Nothing about the pattern says "cache". Keep the shape, change what the proxy decides:
    now it checks who is calling. The real store stays simple — it can trust that
    every call that reaches it was already authorised.


  

    
Demo 3 · access control
code/src/03-protection-proxy.ts

    


delete(docId, user) {
  if (user.role !== "admin") {
    console.log("403 — only admins may delete");
    return;                        // never reaches the store
  }
  this.real.delete(docId, user);   // authorised → delegate
}

      

        

      

    

  







  
04 — the exam questionProxy vs. Decorator vs. Adapter vs. Facade

  
All four wrap something. They are told apart by the question each one answers:

  

    

      
PatternInterfaceThe question it answers

      
        
ProxysameMay this call happen, and when? Controls access.

        
DecoratorsameWhat else should happen around it? Adds behaviour.

        
AdapterdifferentHow do I make these two fit together?

        
Facadenew, simplerHow do I give this whole subsystem one front door?

      
    

  

  

    
The sharpest way to tell Proxy from Decorator: a decorator always delegates —
      it wraps the real call and adds to it. A proxy may decide not to call the real object at all
      (cache hit, denied permission, object not created yet). If your wrapper can return without ever
      touching the real thing, it is a proxy.

  







  
05 — the wow momentJavaScript has this built in

  
Writing a logging proxy by hand means one wrapper method for every method — boring,
    and it grows with the class. JavaScript ships a Proxy object that applies the idea to
    every property at once, with a single handler.


  

    
Demo 5 · native Proxy
code/src/05-native-js-proxy.ts

    


function withLogging(target, label) {
  return new Proxy(target, {
    get(obj, prop) { /* wraps every method automatically */ }
  });
}

      

        

      

      
The same object, zero changes to it, full logging — and it
        works on anything, including a plain calculator. This exact mechanism powers Vue 3
        reactivity and MobX.

§ — glossaryImportant words

  
The vocabulary from the session. The right-hand column is the thing that makes it stick.

  

    

      
WordWhat it meansFix it in memory

      
        
ProxyA stand-in object with the same interface as a real service, controlling access to it.The bouncer in front of the club.

        
SubjectThe shared interface both the proxy and the real object implement. Also called the interface.interface ImageService

        
RealSubjectThe real object doing the actual, usually expensive, work.RemoteImageService

        
ClientThe code calling the interface. It never learns whether it got the proxy or the real thing.openGallery(service)

        
DelegationPassing a call on to another object instead of doing the work yourself.return this.real.fetch(name)

        
Lazy loadingCreating or loading something only at the moment it is first needed.this.real ??= new Real()

        
Cache hit / missHit: the answer was already stored. Miss: it wasn't, so the real call has to happen.3 requests, 2 misses, 1 hit.

        
Virtual proxyStands in for an expensive object, creating or loading it lazily.Demo 2, exercise 1.

        
Protection proxyChecks permissions before letting a call through.Demo 3, exercise 2.

        
Remote proxyLocal stand-in for an object living in another process or on another machine.An RPC stub; a VPN.

        
Logging proxyRecords or times every call without the real class knowing.Demo 5.

        
Cross-cutting concernSomething needed nearly everywhere — logging, timing, auth, retries — that belongs in no single business class.Why proxies exist at all.

        
Open/Closed principleOpen for extension, closed for modification: add behaviour without editing existing code.You never touched RemoteImageService.

        
Structural patternA GoF pattern about how objects are composed. Proxy, Decorator, Adapter and Facade are all structural.Composition, not creation.

        
MiddlewareA layer sitting between request and handler, doing work around it. The web's everyday proxy.Express app.use(...)

      
    

  







  
§ — the non-obvious bitsGood to know

  

    
if (cached) is a bug
An empty string, 0 and false
      are all falsy — so a correctly cached "" counts as a miss and you call the network again,
      forever. Always compare with !== undefined.

    
A cache trades freshness for speed
That trade is not always yours to make.
      Never cache prices, permissions or stock levels without a rule for when the entry expires.

    
Proxies hide where the time goes
The honest cost of the pattern: a stack
      trace gains a layer, and a slow call can hide behind a cheerful cache. Indirection is never free.

    
The client never changes
This is not a side effect — it is the
      pattern. If you had to edit the client to add the proxy, you did not build a proxy.

    
Native Proxy is the same idea, one level down
GoF Proxy is a design you
      write by hand. JavaScript's Proxy is a language feature that applies it to every property
      at once — which is exactly how Vue 3 knows your data changed.

    
You often do not own the real class
The strongest argument for a proxy over
      "just edit the service": it may be a third-party SDK, or shared by teams who did not agree to your change.

  







  
§ — carry this homeThe whole pattern in nine lines

  
If you remember one snippet from today, this is it. Check the cache, maybe delegate, remember the result.


class CachingProxy implements Service {   // 1. same interface as the real thing
  private cache = new Map();
  constructor(private real: Service) {}

  ask(key) {
    const hit = this.cache.get(key);
    if (hit !== undefined) return hit;      // 2. maybe never call the real one
    const value = this.real.ask(key);       // 3. otherwise delegate
    this.cache.set(key, value);             // 4. remember for next time
    return value;
  }
}

  
Line 2 is what makes it a proxy and not a decorator.
